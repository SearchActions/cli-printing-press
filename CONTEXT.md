# CLI Printing Press — Domain Glossary

> Vocabulary this project reasons in. Architecture and refactor work reads this file
> to use the project's own terms. Companion: `docs/adr/` for load-bearing rejections.
> Authoritative upstream conventions live in `AGENTS.md` and `docs/GLOSSARY.md` —
> this file mirrors the canonical terms and adds SearchActions-side framing.

## Project intent
A "printing press" that prints token-efficient Go CLIs, Claude Code skills, and MCP servers for any API or website. Goal: make API surfaces *muscle memory for an agent* — no doc hunting, no wrong turns, no wasted tokens. Output fuses official API docs, community CLI/MCP patterns, sniffed undocumented APIs, and the Steinberger playbook (local SQLite, compound commands, agent-native flags).

## Core entities
- **The Printing Press (the Press)** — The system as a whole: generator + templates + binary + skills. Canonical name in user-facing output. Never call it "the machine" externally.
- **The machine** — Internal shorthand for the generator, templates, parser, and skills. Producing surface. Distinct from a printed CLI.
- **Printed CLI** — A generated binary + skill + MCP server for one API or website. Lives under `~/printing-press/library/<api-slug>/`. Wraps an API; never replaces one.
- **API spec / spec** — Source of truth for generation. Internal YAML under `catalog/specs/` or external OpenAPI 3.0+. Parsed in `internal/openapi/` and `internal/spec/`.
- **Catalog** — Embedded `catalog/*.yaml` entries listing supported APIs. Each entry carries `name`, `display_name`, `description`, `category`, `tier`, `spec_url`, `spec_format`, `openapi_version`, `verified_date`, `homepage`, `notes`, `known_alternatives` and `sandbox_endpoint`. `catalog.FS` is a Go embed; rebuild required after edits.
- **Manuscript** — Pre-publish staging of a printed CLI under `~/printing-press/manuscripts/<api-slug>/`. Distinct from the local library.
- **Local library** — `~/printing-press/library/<api-slug>/`. The user's installed printed CLIs.
- **Public library** — The `printing-press-library` GitHub repo / printingpress.dev. Curated public catalog. Distinct from the embedded catalog.
- **Sniffed API** — An undocumented web API reverse-engineered from network traffic (Google Flights, Dominos, ESPN). The Press supports these as first-class spec inputs alongside official OpenAPI.
- **Tools manifest** — `tools-manifest.json` per printed CLI. The "manifest" without qualifier means this file.
- **Owner vs OwnerName / Printer vs PrinterName** — Two parallel slug-vs-display pairs on `APISpec` and `CLIManifest`. `Owner` is path-safe (`trevin-chow`); `OwnerName` is prose (`Trevin Chow`). `Printer` is the GitHub @handle of the human who ran the Press; `PrinterName` is their display name. Resolution paths are deliberately different — see AGENTS.md.

## Modules
- **`cmd/printing-press/`** — CLI entry point.
- **`internal/spec/`** — Internal YAML spec parser.
- **`internal/openapi/`** — OpenAPI 3.0+ parser.
- **`internal/generator/`** — Template engine + quality gates. The core of the machine.
- **`internal/catalog/`** — Catalog schema validator.
- **`internal/cliutil/` and `internal/mcp/cobratree/`** — Generator-reserved namespaces emitted into every printed CLI. Do not hand-author here.
- **`skills/`** — Claude Code skill definitions that drive the agent loop on top of the binary.
- **`scripts/golden.sh`** — Generator-output stability gate.

## Surfaces
- **CLI surface** — Cobra commands the human invokes.
- **MCP surface** — Tools an agent invokes. Auto-generated by the runtime walker in `cobratree/` mirroring the Cobra tree at server start. Default is *expose*; skip rules are exceptions.
- **Endpoint mirror** — A typed MCP tool generated for a spec endpoint (`pp:endpoint` annotation). GET = read-only + open-world; DELETE = destructive; POST/PUT/PATCH = open-world.
- **Built-in tools** — `context`, `sql`, `search`. Read-only, local-only.

## Gates and verifiers
- **8 quality gates** — `go mod tidy`, `govulncheck`, `go vet`, `go build`, binary build, `--help`, `version`, `doctor`. Generated CLIs must pass all 8.
- **Golden harness** — `scripts/golden.sh verify`. Frozen fixtures under `testdata/golden/expected/`. Never update goldens to make a check pass; only when a behavior change is intentional.
- **Verify** — `printing-press verify` runs printed CLIs against the spec. Treats exit 0 as success unless `pp:typed-exit-codes` annotation declares otherwise.
- **Reimplementation check** — Dogfood scoring + absorb-manifest Kill Check that flags handlers showing neither a real client call nor a store access without an opt-out (`pp:client-call`, `pp:novel-static-reference`).

## Roles / actors
- **Printer (human)** — The person who ran the Press to mint a CLI. Captured as `Printer` (slug) and `PrinterName` (display). Preserved on regen.
- **Owner (API vendor / wrapper author)** — The party the Go module path is rooted under. Captured as `Owner` and `OwnerName`. Distinct from the Printer.
- **Agent (MCP consumer)** — The downstream LLM agent that calls printed-CLI commands as MCP tools. The whole design optimizes their token efficiency.

## Out-of-scope concepts
- **Default printed CLIs we do NOT install in this project** — ESPN, flight-goat, linear-pp-cli. These are upstream-shipped *examples*. We use the Press as the machine, not as a consumer of its sample output.
- **Hand-rolled response builders** — Rejected by the reimplementation check. A printed CLI wraps an API; it does not return constants, hardcoded JSON, or struct literals shaped like a payload.
- **Versions in `marketplace.json` plugin entries** — `TestMarketplaceJSONHasNoPluginVersion` enforces absence.
- **Changes to generator-reserved namespaces** — `internal/cliutil/` and `internal/mcp/cobratree/` are emitted into every printed CLI. Hand-authored code there gets overwritten on regen.
