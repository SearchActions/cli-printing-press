<!-- K-924: a local MCP server can ship arbitrary code execution with NO auth layer to enable -->
- Before exposing ANY locally-registered MCP server beyond loopback, probe it with an unauthenticated `initialize` and require a 401 + `WWW-Authenticate`. Screaming Frog's `POST http://127.0.0.1:11435/mcp` answers `HTTP/1.1 200` with no auth header at all - there is no auth layer to enable - and it ships two host-RCE tools (`sf_npm_install`, `sf_run_node_js_script`, plus `sf_write_text_file` silent overwrite); the printed `screaming-frog-official-pp-mcp` binary that fronts it accepts `--transport http --addr` and has no auth of its own either, so a generated CLI or gateway does NOT inherit auth the wrapped server never had. Port 11435 binds to LOOPBACK always - never published, never proxied raw, never tunnelled onto a shared network, not "temporarily, to test it". If it must be reached remotely, front it with an authenticating proxy (Caddy + oauth2-proxy) AND remove the exec tools from the catalog: tool curation is a security boundary, not a convenience filter. For diagnosis from another machine, SSH-tunnel or run the client on the box; never bind `0.0.0.0`. Incident of record INC-2026-271 (OPEN, SEV:2).
<!-- K-941: Whole-Value PathEscape Encodes the Structural Slashes in a Resource Name -->
- In the templated `replacePathParam` helper, never `url.PathEscape` the whole path-parameter value - it encodes the structural `/` in hierarchical resource names (`properties/456314183`), the route template stops matching, and every path-templated command in every generated CLI returns an HTML 404 while `auth status` still looks fine. Escape PER SEGMENT, but reject empty / `.` / `..` segments first and fall back to whole-value escape for those (a 404 is the safe failure) - plain per-segment escaping is path-parameter injection when an MCP server or agent drives the CLI (INC-2026-147).
<!-- K-963: On Windows the press's own validation legs fail and blame the generated CLI -->
- Before debugging a CLI this repo's harness has condemned on Windows, confirm the harness itself ran. Two known false verdicts: `generate --validate` (the `--help`/`version`/`doctor` gates) and `dogfood --live` build `<cli>-pp-cli-validation` / `<cli>-pp-cli-dogfood` and exec them by BARE PATH without `.exe`, so Windows answers `executable file not found in %PATH%` while the generated CLI builds and runs fine - `verify`/`shipcheck` take a different path and pass, and that asymmetry is the tell; and `verify-skill` prints a U+2713 check mark that a cp1252 console cannot encode, raising `UnicodeEncodeError` so the leg reports FAIL with ZERO findings. An empty findings list beside a FAIL verdict is a crashed reporter, never a clean run that failed. Workarounds: build with the `.exe` suffix and run the matrix by hand (or run that leg on macOS/Linux), and set `PYTHONUTF8=1 PYTHONIOENCODING=utf-8` before `shipcheck`/`verify-skill`. Separately, run `sync --no-cache` before `reconcile`/`diff` right after a live mutation - the client response cache can serve a pre-mutation `GET` list page. See K-963.
<!-- K-964: a locally-installed plugin serves from a CACHED COPY and `plugins update` no-ops without a version bump -->
- A locally-installed Claude Code plugin runs from a CACHED COPY, never from its source tree: `plugins install` against a `marketplace.json` with `"source": "./"` COPIES the tree into `~/.claude/plugins/cache/<marketplace>/<plugin>/<version>/` (verified a plain directory, not a junction/ReparsePoint), and that copy is what loads - so merging to this repo's `main` changes NOTHING about the running tool. The obvious remedy fails just as quietly: `claude plugins update` keys off the VERSION STRING, so material changes merged without a version bump make it print `already at the latest version (1.0.0)` and exit 0 with the stale cache intact. Observed 2026-06-02 - watchtower PR #4 merged while the live plugin kept running the April-14 cached `audit/SKILL.md`, and nothing errored at any step. After changing plugin content: bump the version in ALL THREE places (`plugin.json` `version`, `marketplace.json` `metadata.version` AND `plugins[].version` - `plugins tag` validates they agree), run `plugins marketplace update` then `plugins update`, then RESTART the session (the running process holds the old plugin in memory), and verify by asserting a new marker string is present under the new `<new-version>/` cache directory. Trust neither the merge nor the update's exit code. Corrects K-461, which says the cache is overwritten from source on sync: that sync fires only on a version bump, so editing the source is necessary but NOT sufficient. Phantom-completion class - "merged" is not "installed", and "installed" is not "current".

<!-- K-1033: `os.Chmod` on Windows writes no DACL - a 0600 secrets file inherits its parent ACL -->
- On Windows `os.Chmod` only toggles the read-only attribute and writes no access control list, so a credentials file "restricted" to 0600 inherits its parent directory's permissions - which is why `VerifyCredsPerms` correctly refuses files written into a broadened `%TEMP%`. Fix it at creation time in the generator (explicit owner-only DACL via the win32 security APIs or `icacls /inheritance:r /grant:r` semantics), keep `Chmod` for Unix, and never weaken the read-time guard.
<!-- K-1056: In-place mutation of a shared parsed artifact diverges every cold-parse consumer -->
- When one consumer of a parsed artifact mutates it in place, every other consumer that re-parses from source silently diverges - and the primary path's own tests cannot see it, because the mutation has already run by the time the agreeing consumer reads the artifact (`dedupeFlagIdentifiers` mutating the shared `*spec.APISpec` is why `tools-manifest emit` emits `dry-run-enabled` against CLIs using `dry-run-2-enabled`). Reserved and collision name sets must come from a single source of truth consumed by ALL emitters, never from whichever state one emitter's side effect left behind. Probe by running a fresh parse through the second consumer and diffing its output names against the first consumer's emitted names.
